# OpenWebUI — основа интерфейса

Продукту нужны двум ролям (родитель и ребёнок) загрузка изображений, статусы заданий и диалог с AI. Вместо собственного веб-UI решено взять self-hosted OpenWebUI как основной интерфейс: он уже даёт аккаунты, загрузку файлов, чат и мобильный веб. Наш бэкенд (ADR 0002) подключается к OpenWebUI; кастомный дашборд статусов в MVP не строим — статусы читаются в чате. Электронный журнал позже подключается источником заданий на стороне бэкенда и не меняет этот выбор.

## Considered Options

- Собственный веб-UI: полный контроль UX, но дублирование аккаунтов/файлов/чат-логики ради семьи из двух человек.
- OpenWebUI сайдкаром: два интерфейса и два источника правды по диалогам.

## Consequences

- Кастомный UX ограничен чат-парадигмой; сложные экраны (таблица недели) остаются текстом/разметкой в чате.
- Возврат к своему UI не требует переделки ядра: вся доменная логика живёт в бэкенде.
