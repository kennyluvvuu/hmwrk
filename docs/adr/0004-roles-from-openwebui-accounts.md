# Роли доверяются аккаунтам OpenWebUI

Родитель и ребёнок — отдельные аккаунты OpenWebUI. Ядро не заводит собственную авторизацию: пользовательский контекст приходит с запросами OpenWebUI (заголовки user-info, при необходимости — отдельные API-ключи на роль) и отображается таблицей «пользователь → роль». Разрешения на инструменты проверяются по роли (раздел 4 SPEC).

## Considered Options

- Один общий аккаунт: ребёнок смог бы вызывать родительские действия — отказано.
- Своя авторизация в бэкенде (PIN): дублирует то, что OpenWebUI уже умеет, — отказано.

## Consequences

- Граница доверия — OpenWebUI: компромисс его аккаунта = компромисс роли. Для семейного MVP принимаем.
- Видимость прочих подключённых к OpenWebUI моделей ограничивается группами OpenWebUI (ребёнок видит только наши «модели»).
