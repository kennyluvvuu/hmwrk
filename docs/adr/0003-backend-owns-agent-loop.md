# Ядро владеет агентным циклом, OpenWebUI — тонкий клиент

Вся агентная логика (инструменты парсинга, отчёта, проверки, утверждения, настроек) живёт в нашем TS-бэкенде поверх pi-durable; наружу он отдаёт OpenAI-совместимый `/v1/chat/completions`. OpenWebUI подключает его как «модель» и отвечает только за аккаунты, чат-UX и загрузку файлов. Собственные Tools/Functions и RAG OpenWebUI не используются.

## Considered Options

- **OpenWebUI = мозг**: OpenWebUI ходит в LLM сам, агентность — его Python-Tools/Functions, дёргающие REST-API ядра. Отказано: логика размазывается на TS + Python, две точки правды; pi-durable перестаёт быть «агентным» ядром.
- **MCP-мост**: ядро публикует инструменты как MCP-сервер. Отказано в MVP: поддержка MCP-клиента в OpenWebUI сыровата; механизм можно добавить позже поверх того же ядра.

## Consequences

- Один стек агентной логики; durable-задачи и инструменты в одном коде.
- Придётся самим держать HTTP-эндпоинт (стриминг, форматы OpenAI Chat Completions) — принимаем.
- UX ограничен чатом: сложные экраны не строим (согласовано с ADR 0001).
